RELEASE CHECKS AND THEIR LIMITS

This is a source-only publication audit. At the owner's request, no Lean
compiler invocation, Lake build, dependency fetch, or compiled axiom audit
was performed while preparing this revision. The documented build commands
are for recipients; their inclusion is not a claim of a fresh successful build.

Checks performed:
- Test the original and final ZIP CRCs and inspect archive entry paths.
- Verify the original input SHA256SUMS and regenerated release checksums.
- Compare every .lean file to the original input: identical paths and bytes.
- Inspect the five package configurations, toolchains, and locked revisions.
- Resolve local Lean imports statically against the included source layout,
  respecting the Core4loop sibling dependency on Core3loop. No missing local
  module was identified. This is not Lean import elaboration.
- Inspect README entry points against the actual source declarations.
- Scan text and archive metadata for private local-account identifiers,
  machine-specific paths, credentials, unwanted hidden metadata, and build artifacts.
  No such private identifiers or artifacts were found in the final package.
- Record native_decide occurrences and theorem-scope limitations in
  TRUST_AND_SCOPE.txt. No compiled axiom set is asserted.

The original ZIP had valid integrity data and no detected private paths. It
lacked a license and root release guide; three manifest root package names
were inconsistent with their lakefile.toml. Those non-proof issues are fixed
in this copy. Root-name inconsistency alone was not established to cause a
build failure. No missing Lean source was identified by the static review.

To repeat the file-integrity check without compiling anything, use Python
3.11 or newer from the extracted release root:
  python3 verify_release.py

Alternatively, verify the complete file manifest using either command:
  sha256sum -c SHA256SUMS
  shasum -a 256 -c SHA256SUMS

SHA256SUMS covers every distributed regular file except itself.
PROOF_SOURCE_SHA256SUMS covers only the unchanged original Lean files.
Hashes detect changes relative to the supplied manifest; they are not a
digital signature and do not authenticate the publisher. Static scans do
not guarantee the absence of every conceivable privacy or correctness issue.
This packaging audit is not arXiv acceptance or mathematical certification.
